# Simple English Rule

Use familiar words and complete sentences. Explain a new term when it first appears. Keep the technical limitation even when simplifying the wording.

## Example before theory

Instead of “JWT facilitates stateless authentication,” write:

> An access token lets the server check who sent a request. A signed JWT can carry identity claims that the server verifies. The server still needs to check who may access the requested data.

Instead of “idempotent consumption eliminates duplicate delivery,” write:

> The broker may deliver the event again. The consumer recognizes work it already committed and avoids repeating that database change.

## Editorial checklist

- Introduce one new idea at a time.
- Start with a request, code example, or concrete failure.
- Define acronyms before using them repeatedly.
- Explain why the code is present and what the learner should observe.
- Replace “always,” “guaranteed,” and fixed speedups with the conditions that make the statement true.
- Keep beginner steps separate from optional internals.
- Use prose for explanations, language-specific fences for code, and `console` only for literal output or layouts.

Simple language should make reasoning easier. It should not remove facts about failures, versions, or tradeoffs.
