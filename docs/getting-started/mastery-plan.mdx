# Mastery Plan

Mastery does not come from reading once.

It comes from building, breaking, fixing, explaining, and repeating.

## Three Tracks

Use this guide in three tracks.

```text
Learn    understand the idea
Build    implement the idea in a project
Master   handle mistakes, scale, tests, and production issues
```

Do not skip the build track.

Backend skill becomes real only when your code handles bad input, missing data, slow queries, and failures.

## Weekly Method

```text
Day 1-2  learn topic and write notes
Day 3-4  build small feature
Day 5    write tests
Day 6    debug and refactor
Day 7    explain the topic and review mistakes
```

## Mastery Checklist

For every important topic, you should be able to:

- Explain it in simple English
- Write a working example
- Test the happy path
- Test the failure path
- Name common mistakes
- Debug a broken version
- Explain when not to use it

## Project Ladder

Progress through the capstones in sequence:

- [Todo API](/projects/todo-api-full-build) — CRUD, layers, validation, and error shapes
- [Notes API](/projects/notes-api-full-build) — User authentication, JWT, ownership checks, and Flyway migrations
- [Blog API](/projects/blog-api-full-build) — Roles, permissions, comments, and pagination
- [Ecommerce Backend](/projects/ecommerce-full-build) — Multi-table transactions, payment idempotency, and inventory races
- [Notification Worker](/projects/notification-worker-full-build) — Message queues, worker retries, dead letter queues, and idempotency
- [System Design Implementations](/system-design/fundamentals) — Scale, capacity estimation, rate limiting, and fault tolerance


## Rule

Reading gives vocabulary.

Building gives skill.

Debugging gives judgment.
