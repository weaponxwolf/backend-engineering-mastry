# Curriculum Audit

This page keeps the guide honest.

If a topic is marked mastery-level, it must teach enough to build, test, debug, and explain real systems.

## Current Standard

A topic is not complete when it has only:

- definition
- small snippet
- list of common tools
- interview question list

A topic is complete when it has:

- mental model
- real backend example
- code shape
- data model when needed
- failure cases
- common mistakes
- tests
- production notes
- practice task
- interview answers

## Required Labs

Labs should force learners to solve real problems.

Examples:

- fix N plus one query
- add missing ownership check
- recover failed migration
- debug slow API with logs and metrics
- handle duplicate payment callback
- add idempotency key to checkout
- prevent inventory race condition
- add Testcontainers to repository tests
- deploy Dockerized app with environment config

## Book Replacement Rule

The guide should reduce the need for books by combining:

```text
concept explanation
project implementation
production failure
testing
interview answer
```

Books are still useful for extra depth and different viewpoints.

But this guide should be enough to build serious backend skill without jumping across many disconnected resources.

## Maintenance Rule

Every new page should answer:

- What problem does this solve?
- Where does it appear in a real backend?
- How do I implement it?
- How does it fail?
- How do I test it?
- How do I explain it in interview?

If a page cannot answer these, it is not finished.
